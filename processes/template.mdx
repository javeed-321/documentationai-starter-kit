## Purpose

This template standardizes how teams record repeatable processes inside Notion. Every process page follows the same structure so readers can locate steps, owners, and review dates without searching multiple locations. Use the sections below as the required skeleton for any new process document.

## Steps

Create the process steps inside a Notion database or as a series of toggles. Each step must include a clear action, the expected output, and any linked resources.

<Steps>
  <Step title="Define the trigger" icon="play-circle">
    Identify the event that starts the process. Record the exact condition in the page header so readers know when to follow these instructions.
  </Step>
  <Step title="List required inputs" icon="list">
    Document every piece of information or asset needed before the first action. Add a Notion database property for each input so status can be tracked.
  </Step>
  <Step title="Execute actions in order" icon="check-circle">
    Write each action as a numbered item or toggle. Nest sub-steps inside toggles when they contain optional branches or detailed instructions.
  </Step>
  <Step title="Record the output" icon="file-text">
    State what the completed process produces. Link the output location or template inside the final step.
  </Step>
</Steps>

## Owners

Assign a primary owner and at least one backup for every process. Store these assignments in a Notion database property so updates appear on the process dashboard.

- Primary owner: [Name], [Team]
- Backup owner: [Name], [Team]
- Last updated by: [Name] on [YYYY-MM-DD]

## Review Cadence

Schedule a recurring review so the process stays current. Add the next review date as a Notion database property and link the related runbook or policy pages in the page properties.

- Review frequency: Quarterly
- Next review date: [YYYY-MM-DD]
- Linked runbooks: [Page title]
- Linked policies: [Page title]

Use Notion database filters to surface processes that are past their review date.
