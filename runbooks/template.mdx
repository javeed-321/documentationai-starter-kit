title: Runbook Template
description: Standard runbook format for handling Notion workspace incidents, AI feature troubleshooting, and integration issues.
---

## Trigger

Monitor workspace health dashboards and alert channels for signs of disruption. Common triggers include failed AI agent executions, permission errors on shared databases, or degraded search indexing performance.

Respond when any of the following occur:

- Automated alerts indicate AI agent task failures exceeding threshold.
- Users report inability to access or edit databases.
- Enterprise search returns incomplete or stale results.

## Steps

Follow this sequence to triage and mitigate the incident.

<Steps>
  <Step title="Triage and classify">
    Review alert details and recent activity logs. Identify whether the issue affects AI agents, databases, or permissions.

    Run the following command to gather initial diagnostics:

    ```bash
    notion-cli diagnose --workspace ws-123 --since 1h
    ```
  </Step>
  <Step title="Isolate AI agent failures">
    Check agent execution history and restart stalled processes.

    ```bash
    notion-cli agents restart --id agent-456 --force
    ```
  </Step>
  <Step title="Repair database and permissions">
    Validate database schema and reapply access controls where needed.

    ```bash
    notion-cli db repair --id db-789
    notion-cli permissions sync --workspace ws-123
    ```
  </Step>
</Steps>

## Escalation Path

<Callout kind="alert">
If the issue persists after the steps above or affects production workspaces, escalate immediately to the on-call engineer. Provide the incident ID and output from all diagnostic commands.
</Callout>

## Rollback

Revert recent configuration changes or agent deployments if mitigation introduces new errors.

```bash
notion-cli agents rollback --id agent-456 --to previous
notion-cli permissions restore --workspace ws-123 --timestamp 2024-10-01T12:00:00Z
```

Confirm workspace stability before closing the incident.
