## Trigger

This runbook activates when an incident affects pages or databases in the Notion workspace. Common triggers include sync failures between the desktop client and the server, permission errors on shared pages, or query timeouts when users access embedded views. Check the workspace activity log before proceeding.

## Steps

Open the incident page in Notion and embed the status database at the top of the page. Use the /embed command and select the "Incident Status" database view filtered to the current date.

Update the database entry to mark the incident as "In Progress". Then run the following command to force a full sync on the affected workspace:

```bash
curl -X POST https://api.example.com/notion/sync \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"workspace_id": "ws_12345"}'
```

Verify that all linked pages load without errors. If the embedded database shows stale data, refresh the view manually from the page menu.

## Escalation Path

<Callout kind="alert">
If the sync command returns a 5xx error or the database embed fails to update, contact the on-call engineer at oncall@example.com or page via the internal Slack channel #notion-oncall. Provide the incident ID and the last sync timestamp from the workspace logs.
</Callout>

## Rollback

Revert the workspace to the last known good state by restoring from the Notion page history. Select the version saved before the incident trigger time and publish the restored page. Run the sync command again with the rollback flag:

```bash
curl -X POST https://api.example.com/notion/sync \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"workspace_id": "ws_12345", "rollback": true}'
```

Confirm that the status database reflects the restored state before closing the incident.
