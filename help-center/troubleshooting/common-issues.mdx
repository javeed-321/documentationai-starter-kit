## Common Issues

We understand how disruptive these problems can feel when you're trying to help customers. Each expandable below walks through a specific symptom, its likely cause, and the exact steps to resolve it.

<Expandable title="Messenger not appearing" default-open="false">

The Intercom Messenger bubble fails to display on your site, leaving visitors without a way to reach support.

**Cause:** The embed script references an incorrect workspace ID or loads after the page has already rendered.

**Fix:** Open your site in a browser and check the console for this exact message:

```
Intercom: Messenger failed to initialize. Verify your workspace ID.
```

Update the script tag in your HTML head to match the ID shown in your Intercom settings exactly:

```html
<script>
  window.intercomSettings = { app_id: "YOUR_WORKSPACE_ID" };
</script>
<script async src="https://widget.intercom.io/widget/YOUR_WORKSPACE_ID"></script>
```

Refresh the page and confirm the bubble appears in the bottom-right corner.

</Expandable>

<Expandable title="Chat connection issues" default-open="false">

Visitors see the Messenger but receive the error "Connection to Intercom failed. Please try again later." when they open a conversation.

**Cause:** A browser extension or content-security-policy header blocks the required WebSocket connection to Intercom servers.

**Fix:** Temporarily disable extensions and test again. If the issue persists, add these entries to your site's content-security-policy header:

```
connect-src https://api.intercom.io wss://nexus-websocket-a.intercom.io;
```

Once updated, ask a test visitor to open the Messenger and start typing. The connection status should change from "Connecting..." to "Connected" within a few seconds.

</Expandable>

<Expandable title="Article search problems" default-open="false">

Search in the help center returns "No articles found" even though matching content exists in your Collection.

**Cause:** Articles were published without being added to an active Collection, so the search index never included them.

**Fix:** In your Intercom workspace, go to Help Center > Collections. Select the relevant Collection and click "Add articles." Choose the missing articles and save. Rebuild the search index by clicking "Update search" in Collection settings. Test the search term again in your live help center to confirm results now appear.

</Expandable>

<Expandable title="Notification failures" default-open="false">

You receive the error "Notification delivery failed: 403 Forbidden" when testing email or in-app notifications for new help center articles.

**Cause:** The notification rule references an outdated or revoked API token instead of the current workspace credentials.

**Fix:** Generate a fresh access token in Intercom under Settings > Integrations > API keys. Replace the token in your notification rule configuration:

```
Authorization: Bearer YOUR_NEW_ACCESS_TOKEN
```

Save the rule and send a test notification to yourself. The delivery status should update to "Sent" within one minute.

</Expandable>
