## Install apps and connect your stack

If you are trying to add an app, set up a custom action, or map data between systems, this page shows the quickest path. Use it to install marketplace apps, connect partner solutions, and keep the right fields in sync.

<Callout kind="info">
  Before you install anything, confirm your admin role and check which fields you want to send or receive. That makes setup faster and helps avoid broken mappings later.
</Callout>

## Install a marketplace app

Use these steps when you want to add a prebuilt integration from the marketplace.

<Steps>
  <Step title="Open the marketplace" icon="package">

    Go to the marketplace and search for the app you want to install. Use the app name, vendor name, or a keyword that matches the workflow you need.

  </Step>
  <Step title="Review the app details" icon="help-circle">

    Check what the app does, which objects it connects, and whether it supports the data you need. Pay close attention to permissions, required plans, and any setup notes.

  </Step>
  <Step title="Install and authorize" icon="check-circle">

    Select the app, then complete the authorization flow. Grant only the permissions needed for the integration to work.

  </Step>
  <Step title="Configure the app" icon="settings">

    Add account details, field mappings, routing rules, or sync preferences. Save your changes and run a test action if the app offers one.

  </Step>
</Steps>

## Create a custom action

Custom actions let you send data to an external system or trigger a specific workflow when a ticket changes.

<Steps>
  <Step title="Choose the trigger" icon="zap">

    Pick the event that should start the action, such as ticket creation, status change, or an update to a specific field.

  </Step>
  <Step title="Define the action" icon="settings">

    Set the endpoint, request method, and payload. Include only the fields the destination system needs.

  </Step>
  <Step title="Map your data" icon="database">

    Match Zendesk ticket fields to the target system fields. Use clear names for values such as requester, priority, status, and custom fields.

  </Step>
  <Step title="Test the action" icon="check">

    Run a test with a real example record. Confirm that the right data arrives and that the receiving system handles the response as expected.

  </Step>
</Steps>

## Map data safely

Good mapping keeps tickets, user details, and workflow updates aligned across systems.

| Mapping need | Best practice | Why it helps |
| --- | --- | --- |
| Ticket fields | Map only the fields you actually use | Keeps payloads smaller and easier to support |
| User data | Use consistent IDs and email addresses | Reduces duplicate records |
| Status updates | Match open, pending, solved, and closed states carefully | Prevents workflow errors |
| Custom fields | Document each field before you sync | Makes future changes easier |
| Sync direction | Choose one-way or two-way sync on purpose | Avoids conflicting updates |

<Callout kind="tip">
  Start with one workflow first, then expand after you confirm the data mapping works. A smaller rollout is easier to troubleshoot.
</Callout>

## Partner solutions

Partner solutions are useful when you need a specialized app, a prebuilt workflow, or help with complex setup.

| When to use a partner solution | What you get |
| --- | --- |
| You need a specialized business workflow | A solution built for a specific use case |
| You want faster setup | Prebuilt configuration and support |
| You need to connect multiple systems | Help coordinating data across apps |
| You need custom development | Guidance for advanced integration work |

## Common questions

<Expandable title="Why does an installed app not show the data I expected?" default-open="false">

  Check the field mapping first. Most missing data comes from a field that was not mapped, a permission that was not granted, or a test record that did not include the right values.

</Expandable>

<Expandable title="Can I use custom actions for more than one workflow?" default-open="false">

  Yes. You can create separate actions for different triggers or endpoints. Keep each action focused so it is easier to test and maintain.

</Expandable>

<Expandable title="What should I do if a partner solution fails during setup?" default-open="false">

  Confirm the app is authorized, check the required permissions, and verify the setup notes from the partner. If the issue continues, capture the exact error and the step where it failed.

</Expandable>
