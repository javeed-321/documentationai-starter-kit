## Overview

MetricsFlow delivers real-time analytics that processes at least 50,000 events per second with end-to-end latency under 50 milliseconds. The platform supports aggregations over more than one billion records while maintaining exactly-once semantics. You define custom metrics, apply time-window aggregations, and connect directly to BI tools without exporting data.

## Time-Window Aggregations

Time-window aggregations let you compute sums, averages, and percentiles over sliding or tumbling windows. You choose window duration and slide interval to match your query patterns.

<Callout kind="info">
Use tumbling windows for periodic reports and sliding windows for continuous monitoring.
</Callout>

## Exactly-Once Processing Guarantees

MetricsFlow guarantees exactly-once processing even during failures or restarts. Every event is processed once and only once before it contributes to any aggregation.

<Tabs>
  <Tab title="Default" icon="check-circle">
    The default setting enables exactly-once delivery with automatic checkpointing every 30 seconds.
  </Tab>
  <Tab title="High Throughput" icon="zap">
    Switch to at-least-once mode when sub-10ms latency matters more than strict guarantees.
  </Tab>
</Tabs>

## Custom Metric Definitions

Define metrics using a simple configuration language. Each metric specifies source events, aggregation function, and window parameters.

```yaml
metric:
  name: order_value_5m
  source: orders
  aggregation: sum(amount)
  window: 5m
  slide: 1m
```

## Integration with BI Tools

Connect MetricsFlow to popular BI tools through standard SQL interfaces or direct connectors. Queries execute against live aggregates without data movement.

<CodeGroup tabs="SQL,Python">
```sql
SELECT
  metric_name,
  value,
  window_start
FROM metrics
WHERE metric_name = 'order_value_5m'
  AND window_start > now() - interval '1 hour';
```
```python
import metricsflow

client = metricsflow.Client(api_key="YOUR_API_KEY")
result = client.query(
    "SELECT value FROM metrics WHERE metric_name = 'order_value_5m'"
)
```
</CodeGroup>

## Best Practices

- Start with 1-minute windows and increase duration only when query volume requires it.
- Enable exactly-once processing for financial or compliance metrics.
- Test custom metric definitions in a staging environment before promoting them to production.
- Use the BI connector with read-only credentials to limit access scope.
