## Overview

Notion AI agents help you keep work moving without adding extra infrastructure. You use them to answer questions from your workspace, route tasks to the right people, generate reports, and reduce repetitive manual work. Because Notion combines notes, docs, projects, calendars, mail, and knowledge in one place, your agents can work across connected context instead of isolated apps.

Use this guide as a starter template when you want to design a practical agent workflow. The examples below show how to think about agent scope, data sources, and handoff points. Keep the first version small: one problem, one audience, one measurable outcome.

<Callout kind="info">
Start with a narrow use case, such as triaging requests or summarizing meetings, before you expand to broader automation.
</Callout>

## Build custom agents

A custom agent is a focused assistant that performs a repeatable job inside your workspace. In Notion, the best agents usually do one of three things: collect information, transform information, or route information. Define the trigger, the inputs, and the expected output before you build anything else.

For example, you can create an agent that turns incoming requests into structured project entries, or one that drafts weekly status updates from completed tasks. The key is consistency. If people cannot predict what the agent will do, they will stop trusting it.

<Steps>
  <Step title="Define the job" icon="settings">
    Write one sentence that states what the agent does and for whom.

    - “Summarize meeting notes for the product team.”
    - “Route support requests to the right owner.”
    - “Draft a weekly report from completed work.”
  </Step>
  <Step title="Choose the source content" icon="database">
    Point the agent at the pages, databases, or team spaces it should use as context.

    Keep the scope tight at first so the agent answers from trusted content only.
  </Step>
  <Step title="Specify the output" icon="check-circle">
    Decide whether the agent should return a summary, a task list, a report, or a recommended action.
  </Step>
  <Step title="Test with real examples" icon="play-circle">
    Run the agent on recent work and adjust the prompt, scope, or output format until the result is reliable.
  </Step>
</Steps>

### Example starter prompt

Use a prompt like this when you are drafting your own agent behavior:

<CodeGroup tabs="Prompt,Output">
  ```text
You are a workspace assistant for the product team.
Use only the linked project pages and meeting notes.
Return a concise summary, the next actions, and any blocked items.
If information is missing, say what you need.
  ```

  ```text
Summary
- Release planning is on track.
- Two items need review.

Next actions
- Assign owner for design approval.
- Update launch checklist.

Blocked items
- Waiting on final copy.
  ```
</CodeGroup>

## Meeting notes and writing assistant

Notion AI can help you turn meetings into useful documentation and written output. Meeting notes are most valuable when they capture decisions, open questions, and assigned follow-ups in a consistent format. Writing assistance is equally useful when you need to rewrite rough notes into a clearer update, doc, or summary.

Use this workflow to move from raw conversation to shareable output. First, capture the meeting context. Then, ask for a structured summary. Finally, refine the draft for the audience that will read it.

<Tabs>
  <Tab title="Meeting notes" icon="book-open">
    After a meeting, ask Notion AI to produce:

    - Key decisions
    - Action items with owners
    - Risks and blockers
    - Follow-up questions

    This works well for standups, planning sessions, and customer calls.
  </Tab>
  <Tab title="Writing assistant" icon="code">
    Use writing help when you need to:

    - Shorten a long draft
    - Rewrite for clarity
    - Change tone for leadership or a broader team
    - Convert bullet notes into a polished summary

    Keep the source material close so the rewrite stays accurate.
  </Tab>
</Tabs>

<Callout kind="tip">
If the result feels too generic, add the audience, purpose, and desired format directly to the request.
</Callout>

## Enterprise search configuration

Enterprise search works best when you connect it to the content people already rely on. In Notion, that means keeping docs current, naming pages clearly, and organizing knowledge so important answers are easy to locate. Search quality depends on both content quality and workspace structure.

Think in terms of retrieval. If an agent cannot find the right page, it cannot answer confidently. Review your top knowledge areas, remove duplicate pages, and make ownership clear for key docs. That gives search a better base to work from.

<Expandable title="Search configuration checklist" default-open="false">
  Before you launch search broadly, review these basics:

  - Keep page titles specific and descriptive.
  - Store canonical process docs in one place.
  - Use clear ownership for policies and reference pages.
  - Remove or archive outdated duplicates.
  - Group related content into predictable spaces.

</Expandable>

### A simple configuration pattern

| Area | What to do | Why it matters |
| --- | --- | --- |
| Core docs | Keep authoritative pages current | Search returns better answers |
| Team spaces | Group related content by function | People find the right context faster |
| Naming | Use specific page titles | Reduces ambiguity in results |
| Ownership | Assign owners to important pages | Keeps knowledge trustworthy |

## Routing work and generating reports

Agents become especially useful when they move work forward without manual follow-up. In Notion, you can route requests, update project status, and generate recurring reports from the same workspace data. This is the difference between a helpful assistant and a passive summary tool.

Start by deciding what “done” looks like. For routing, that might mean assigning an owner and setting a due date. For reporting, that might mean pulling completed items, highlighting risks, and summarizing progress for the week. The more consistent the structure, the easier it is to automate.

<Steps>
  <Step title="Set the routing rule" icon="arrow-right">
    Define how the agent decides where a request should go.

    Examples:

    - Send product questions to the product lead.
    - Send bug reports to the engineering queue.
    - Send launch tasks to the project owner.
  </Step>
  <Step title="Map the report data" icon="bar-chart">
    Choose the source pages or databases that contain the status you want to summarize.

    Use a consistent status field so the report stays accurate.
  </Step>
  <Step title="Generate and review" icon="check">
    Ask the agent to draft the report, then review the tone, dates, and action items before you share it.
  </Step>
</Steps>

## Best practices

Keep your first agents specific, observable, and easy to improve. A good agent is not the one with the broadest scope. It is the one that produces reliable outcomes from trusted workspace content.

- Define one job per agent.
- Limit the agent to the most relevant pages and databases.
- Use consistent page titles and status values.
- Review outputs before you rely on them for external communication.
- Revisit prompts after real usage to remove ambiguity.
- Expand gradually from one team workflow to another.

<Callout kind="success">
When you keep inputs clean and the scope focused, Notion AI agents can support work around the clock without creating extra process overhead.
</Callout>
