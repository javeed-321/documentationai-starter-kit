## Rate Limiting Errors

<Expandable title="ERR_429_RATE_LIMIT" default-open="false">

Exceeded ingestion rate of 50000 events per second.

```json
{
  "error": "ERR_429_RATE_LIMIT",
  "message": "Request rate exceeds 50000 events/sec limit",
  "retry_after": 5
}
```

Send fewer than 50000 events per second to the `/v1/ingest` endpoint at `https://api.example.com`. Implement client-side backoff using the `retry_after` value before retrying.

</Expandable>

<Expandable title="ERR_429_QUOTA_EXCEEDED" default-open="false">

Throughput quota reached for the current billing period.

```json
{
  "error": "ERR_429_QUOTA_EXCEEDED",
  "message": "Monthly event quota of 1e12 records exhausted",
  "quota_reset": "2024-11-01T00:00:00Z"
}
```

Reduce event volume or upgrade the plan. Monitor usage via the dashboard at `https://dashboard.example.com/usage`.

</Expandable>

## Query Syntax Validation

<Expandable title="ERR_400_INVALID_QUERY" default-open="false">

Query contains unsupported syntax or references nonexistent fields.

```json
{
  "error": "ERR_400_INVALID_QUERY",
  "message": "Unknown field 'user_id' in aggregation clause"
}
```

Validate field names against the schema returned by `GET /v1/schema`. Use only supported aggregation functions such as `sum`, `avg`, and `count_distinct`.

</Expandable>

## Data Freshness Issues

<Expandable title="ERR_503_STALE_DATA" default-open="false">

Query requests data newer than the 50 ms freshness window.

```json
{
  "error": "ERR_503_STALE_DATA",
  "message": "Requested timestamp 2024-10-05T12:00:00Z exceeds last committed batch"
}
```

Wait at least 50 ms after event ingestion before querying. Use the `last_updated` timestamp from `GET /v1/status` to confirm data availability.

</Expandable>

## Aggregation Failures

<Expandable title="ERR_500_AGGREGATION_TIMEOUT" default-open="false">

Aggregation over more than 1 billion records exceeded the 30-second timeout.

```json
{
  "error": "ERR_500_AGGREGATION_TIMEOUT",
  "message": "Query exceeded 30s limit on 1.2e9 records"
}
```

Add time-range filters or increase the `timeout` parameter up to 120 seconds on the `/v1/query` endpoint. Split large queries into smaller date-bounded requests.

</Expandable>
