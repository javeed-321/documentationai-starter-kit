## Product and Inventory Errors

<Expandable title="400: Invalid variant option value">
Problem: Creating or updating a product returns an error when a variant option exceeds allowed values.

Cause: The request body contains an option value longer than 255 characters or uses unsupported characters.

Fix: Trim the option value and resubmit.

```json
{
  "errors": {
    "variant": ["Option value is too long"]
  }
}
```

</Expandable>

<Expandable title="422: Insufficient inventory quantity">
Problem: Adjusting inventory levels fails when the requested quantity would result in negative stock.

Cause: The `available` field in the inventory adjustment payload is lower than the current committed quantity.

Fix: Query current inventory first, then apply an adjustment that respects the available count.

```bash
curl -X POST https://api.example.com/admin/api/2024-01/inventory_levels/adjust.json \
  -H "X-Shopify-Access-Token: YOUR_API_KEY" \
  -d '{"location_id":123,"inventory_item_id":456,"available_adjustment":-10}'
```

</Expandable>

## Payment and Checkout Failures

<Expandable title="402: Payment processing declined">
Problem: A checkout completes the order creation step but the payment gateway returns a decline.

Cause: The card issuer rejected the authorization with code `insufficient_funds`.

Fix: Prompt the customer to use an alternate payment method and retry the `complete` mutation.

```json
{
  "errors": {
    "checkout": ["Payment was declined. Reason: insufficient_funds"]
  }
}
```

</Expandable>

<Expandable title="422: Invalid shipping address">
Problem: Submitting a checkout with a shipping address fails validation.

Cause: The `address1` field is missing or the postal code does not match the selected country.

Fix: Validate the address client-side before calling the checkout update endpoint.

```json
{
  "errors": {
    "shipping_address": ["Address1 can't be blank", "Zip is invalid"]
  }
}
```

</Expandable>

## Rate Limit and Authentication Errors

<Expandable title="429: API rate limit exceeded">
Problem: Requests return HTTP 429 after a burst of calls to product or order endpoints.

Cause: The shop has exceeded the 2 requests per second bucket limit.

Fix: Implement exponential backoff using the `Retry-After` header value.

```bash
HTTP/1.1 429 Too Many Requests
Retry-After: 2
```

</Expandable>

<Expandable title="401: Invalid access token">
Problem: All authenticated requests return 401 immediately after token rotation.

Cause: The `X-Shopify-Access-Token` header contains an expired or revoked private app token.

Fix: Generate a new token in the Shopify admin and update the header value.

```bash
curl -X GET https://api.example.com/admin/api/2024-01/products.json \
  -H "X-Shopify-Access-Token: YOUR_API_KEY"
```

</Expandable>
