## API Error Responses

Stripe returns structured error objects for every failed request. Inspect the `type` and `code` fields to determine the exact failure.

<ExpandableGroup>
<Expandable title="card_declined with insufficient_funds">

Problem:  
A charge request returns the error code `card_declined` and message `"Your card has insufficient funds."`

Cause:  
The issuing bank rejected the authorization because the account balance is lower than the attempted amount.

Fix:  
Prompt the customer for a different card or reduce the charge amount. Example response handling:

````json
{
  "error": {
    "type": "card_error",
    "code": "insufficient_funds",
    "message": "Your card has insufficient funds."
  }
}
````

</Expandable>
<Expandable title="refund_failed due to already_refunded">

Problem:  
A refund call returns `"Refund failed: charge already refunded."`

Cause:  
The charge has already been fully refunded or the refund amount exceeds the remaining capturable balance.

Fix:  
Check the charge status with the retrieve endpoint before attempting another refund. Only request refunds on charges whose `status` is `succeeded` and `amount_refunded` is less than `amount`.

</Expandable>
<Expandable title="rate_limit_error">

Problem:  
Requests begin returning HTTP 429 with code `rate_limit_error` and message `"Too many requests."`

Cause:  
The account exceeded the allowed request rate for the specific endpoint.

Fix:  
Implement exponential backoff and respect the `Retry-After` header. Example retry logic:

````javascript
const delay = (ms) => new Promise((r) => setTimeout(r, ms));
async function callWithBackoff(fn, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      return await fn();
    } catch (err) {
      if (err.status !== 429) throw err;
      await delay(1000 * Math.pow(2, i));
    }
  }
}
````

</Expandable>
<Expandable title="parameter_unknown on refund metadata">

Problem:  
A refund creation request fails with `"parameter_unknown: metadata[invalid_key]"`.

Cause:  
The `metadata` object contains a key that is not a string or exceeds 500 characters.

Fix:  
Ensure every metadata value is a string and that keys follow the pattern `[a-zA-Z0-9_-]`. Re-submit the request with sanitized metadata.

</Expandable>
