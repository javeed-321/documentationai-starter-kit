## Overview

Stripe authenticates every API request with credentials that identify your account and control access. Requests without valid credentials return an error. Use secret keys for server-side calls and publishable keys for client-side code.

## Authentication methods

<Tabs>
  <Tab title="API keys" icon="key">
    Include your secret key in the Authorization header of every request. Prefix the value with `Bearer`.

    <ParamField header="Authorization" param-type="string" required="true">
      The string `Bearer` followed by your secret key.
    </ParamField>
  </Tab>
  <Tab title="Webhook signatures" icon="shield">
    Verify that webhook events originate from Stripe by checking the signature header against your endpoint secret.
  </Tab>
  <Tab title="OAuth for Connect" icon="link">
    Use OAuth to obtain access tokens that let you act on behalf of connected accounts.
  </Tab>
  <Tab title="Restricted keys" icon="lock">
    Generate keys with limited permissions for specific services or team members.
  </Tab>
</Tabs>

## Implementation

Store keys in environment variables and never commit them to source control.

```bash
STRIPE_SECRET_KEY=sk_test_...
STRIPE_PUBLISHABLE_KEY=pk_test_...
```

Send authenticated requests with the secret key.

<CodeGroup tabs="cURL,Python,Node.js">
```bash
curl https://api.example.com/v1/charges \
  -H "Authorization: Bearer $STRIPE_SECRET_KEY"
```

```python
import os
import requests

headers = {
    "Authorization": f"Bearer {os.environ['STRIPE_SECRET_KEY']}"
}
response = requests.get("https://api.example.com/v1/charges", headers=headers)
```

```javascript
const response = await fetch("https://api.example.com/v1/charges", {
  headers: {
    Authorization: `Bearer ${process.env.STRIPE_SECRET_KEY}`,
  },
});
```
</CodeGroup>

## Security considerations

<Callout kind="alert">
  Never expose secret keys in client-side code or public repositories. Rotate keys regularly and restrict their scope when possible.
</Callout>
