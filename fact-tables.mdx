## What are fact tables?

<div className="fact-intro">
Fact tables contain quantitative data, typically numerical values that represent the measurements or metrics of a business process. For instance, in a sales environment, a fact table might record each sale transaction, with columns representing details such as transaction ID, sale amount, product ID, and date of sale. Each row in the fact table corresponds to a unique event or transaction and often references multiple dimension tables, which provide context to the facts.
</div>

<Callout type="info" title="Note">
  By default, fact tables are not onboarded for all organisations. To enable them, raise a JIRA ticket with the Capillary Product Support team.
</Callout>

## Key concepts

<div className="concept-grid">
  <div className="concept-card">
    <span className="concept-icon">📋</span>
    <h4>Fact Table</h4>
    <p>Stores measurable, quantitative data — the numbers you analyze. Each row is one event or transaction.</p>
  </div>
  <div className="concept-card">
    <span className="concept-icon">🏷️</span>
    <h4>Dimension Table</h4>
    <p>Stores descriptive attributes — the context around your facts. Think product names, customer info, dates.</p>
  </div>
  <div className="concept-card">
    <span className="concept-icon">🔑</span>
    <h4>Foreign Keys</h4>
    <p>Links between fact and dimension tables. Each fact row references dimensions to add meaning to the numbers.</p>
  </div>
  <div className="concept-card">
    <span className="concept-icon">📐</span>
    <h4>Measures vs Attributes</h4>
    <p>Measures are the numeric values you aggregate (sum, avg). Attributes are the categories you group by.</p>
  </div>
</div>

## Example structure

Here's what a typical sales fact table looks like:

| Column | Type | Description |
|---|---|---|
| `transaction_id` | Primary Key | Unique identifier for each sale |
| `customer_id` | Foreign Key | References the Customer dimension |
| `product_id` | Foreign Key | References the Product dimension |
| `store_id` | Foreign Key | References the Store dimension |
| `sale_amount` | Measure | Total value of the transaction |
| `quantity` | Measure | Number of items purchased |
| `date_of_sale` | Foreign Key | References the Date dimension |

<ExpandableGroup>
  <Expandable title="Badges">
    Tracks badge-related events including badge issuance, badge earning, and badge expiry for customers in the loyalty program. Use this table to analyze badge distribution and engagement patterns.
  </Expandable>

  <Expandable title="Bill Line Items">
    Records individual line-item details from customer transactions. Each row represents a single product or SKU within a bill, including quantity, price, discount, and associated attributes.
  </Expandable>

  <Expandable title="Call Task Customer Status">
    Captures the status of outbound call tasks assigned to agents. Includes task creation, assignment, completion, and outcome data for customer engagement tracking.
  </Expandable>

  <Expandable title="Communication Credits Log">
    Logs all communication credit transactions — issuance, consumption, and expiry. Useful for monitoring messaging budgets and channel-level spend.
  </Expandable>

  <Expandable title="Contact Info">
    Stores customer contact detail change events, including email, phone, and address updates. Enables audit trails for customer data modifications.
  </Expandable>

  <Expandable title="Coupons">
    Tracks coupon lifecycle events — creation, issuance, redemption, and expiry. Analyze coupon performance, redemption rates, and campaign effectiveness.
  </Expandable>

  <Expandable title="Customer Summary">
    Provides an aggregated snapshot of each customer's transaction history, loyalty tier, lifetime value, and engagement metrics. Ideal for segmentation and cohort analysis.
  </Expandable>

  <Expandable title="Daily Till Summary">
    Summarizes daily point-of-sale activity at the till level. Includes total transactions, revenue, average basket size, and other daily KPIs per store register.
  </Expandable>

  <Expandable title="Goodwill Requests">
    Tracks manual goodwill point or reward issuance requests made by store associates or support teams, including approval status and reason codes.
  </Expandable>

  <Expandable title="Nsadmin Messages">
    Records messaging events across channels (SMS, email, push, WhatsApp). Includes delivery status, template details, and campaign linkage.
  </Expandable>

  <Expandable title="Payment Details">
    Captures payment-level breakdown for transactions, including payment mode, tender type, amount, and gateway details for each bill.
  </Expandable>

  <Expandable title="Points">
    Logs all loyalty points transactions — earning, redemption, expiry, and transfers. Core table for loyalty program analytics and liability reporting.
  </Expandable>

  <Expandable title="Profile Users">
    Stores customer profile registration and update events. Tracks onboarding source, registration channel, and profile completeness metrics.
  </Expandable>

  <Expandable title="Registration Event">
    Captures the initial customer registration event with timestamp, source, store, and channel information. Key table for acquisition analysis.
  </Expandable>

  <Expandable title="Return Bill Line Item">
    Records returned line items at the product level. Includes return reason, refund amount, and linkage back to the original transaction.
  </Expandable>

  <Expandable title="Streaks">
    Tracks customer streak-based engagement activities. Records consecutive action completions, streak milestones, and reward triggers.
  </Expandable>
</ExpandableGroup>
